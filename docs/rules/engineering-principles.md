# 工程设计与编码原则（Python 版）

> 对应根索引 [AGENTS.md](../../AGENTS.md)，移植自 C++/Go 服务端仓 `docs/rules/engineering-principles.md` 并结合 Python 服务端实践。适用于新增、修改、重构与评审。

原则冲突时按以下顺序取舍：

`正确性 / 安全 / 数据强一致性 / 向后兼容 > 简单 / 可读 / 与仓库一致 > 可维护 / 可测试 > 有数据支撑的性能 > 假想扩展`

## 1. 模块与职责（SOLID 与 23 种设计模式）

- **单一职责（SRP）与高内聚低耦合**：协议适配、领域逻辑、存储访问与副作用清晰分离，依赖单向不成环；优先显式传参或依赖注入，克制隐式模块级可变全局状态。
- **开闭（OCP）/ 里氏替换（LSP）/ 接口隔离（ISP）/ 依赖倒置（DIP）**与**组合优于继承**：通过 `Protocol` 或轻量组件组合隔离变化点，不造无隔离价值的连续透传包装。
- **23 种经典设计模式的使用原则**：如果某个结构确实适合用 GoF 23 种设计模式（如策略、状态、工厂、适配器、责任链、观察者、装饰器、命令等）来解耦、消除巨型 `if/elif` 分支或隔离明确变化轴，**主动采用或向程序建议采用，并明确告诉程序为什么用这个模式**（解决了什么具体耦合/扩展/维护痛点、替代了什么更糟的写法）；严禁为了套模式而无故堆砌抽象层。
- **系统 / 模块间消息通信（Actor 隔离，两层边界，强制）**：
  - **硬 Actor 边界（必须走不可变消息 / 串行消费）**：**跨进程、跨协程队列、跨服务（含单机 `LocalServiceHub` 桥接）及跨玩家**交互（玩家 A 绝不能无锁读写或覆写玩家 B 的快照/对象），一律通过显式定义的**不可变消息**（`frozen=True` dataclass / 序列化 `bytes` / `PlayerInbox` / RPC / Kafka）通信；严禁队列传可变 protobuf 或非 frozen 对象，严禁跨模块穿透访问 `_private` 字段或方法；各玩家/模块按单队列串行消费并显式处理超时、乱序与重复投递。
  - **同玩家单次提交内强原子联动（状态私有 + 窄服务接口）**：同一玩家单次 `commit_player_data` 内的强原子多域联动保留同步组合语义，但必须经由目标模块的公开窄接口读写其负责的数据切片，禁止跨模块直调 `_save` / `_present` 等下划线私有实现。
  - **作用边界清晰（防过度设计）**：上述约束仅适用于跨系统 / 跨玩家 / 跨队列 / 跨进程边界；单个模块内部仍用正常直接方法调用，**严禁把模块内部普通函数或内聚逻辑无意义地拆成消息**。

## 2. 简单、标准、可读与开源库选型

- **KISS / YAGNI / DRY**：未上线阶段玩家数据与库表可清空重构，按最标准、直达的方案落地，不做冗余历史兼容层；发现问题当场闭环修复。
- **命名第一原则**：详见 [naming-and-boundaries.md](naming-and-boundaries.md)——所有命名必须清晰易懂、语义完全准确并标明单位。
- **第三方开源库选型（先标准库，再找同语言 GitHub 高 Star，交由程序决策）**：
  1. **优先标准库**：先用 Python 标准库和项目既有依赖；标准库能简洁解决的不引入第三方库。
  2. **按当前开发功能的语言去 GitHub 找同语言库**：标准库没有、且成熟开源库比手写更稳妥时，开发 Python 功能就去 GitHub 找 **Python 生态**同类头部高 Star 且活跃、安全、协议兼容的项目（Star 门槛按该语言生态体量浮动——Python 大生态通用库可参考 ≥ 2 万 Star，垂直细分库按 Python 同类头部与维护质量综合评估）。
  3. **交由程序决定并说明原因**：不擅自默默引入新依赖，把候选库与“是否自研”交给程序决定，并清楚说明为什么（标准库的不足、该库解决什么核心痛点、引入维护与安全代价及替代方案对比）。安全永远优先于 Star 数。

## 3. 正确性、线程/异步与实例布局分层

- **Fail-closed 与边界校验**：入口严格校验不可信输入，资产/权限路径默认 fail-closed，不吞异常、不伪装成功；不随便新起后台线程（除非压测证实瓶颈并先与程序/负责人确认说明原因）。
- **实例与布局分层**：实例层只描述实体（「是什么」：`guid` / `config_id` / `equip_kind` / 数量 / 状态 / 时间戳），布局层只描述排列（「摆在哪」：槽位、格子、顺序）；不靠 `list` 下标承载业务槽位顺序；纯内存展示态不写进持久化 proto。
- **面向接口测试**：新增非平凡逻辑与修 bug 必须配确定性 `pytest` 回归测试，无实际运行证据不得声称通过。
